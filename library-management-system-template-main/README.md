# ‫پروژه نهایی جاوااسکریپت - دوره‌ی ۱۱

## ‫سیستم مدیریت کتابخانه

‫در این پروژه، شما باید یک سیستم مدیریت کتابخانه کامل پیاده‌سازی کنید. بک‌اند این پروژه از قبل آماده شده و روی سرور قرار گرفته است. شما فقط باید فرانت‌اند را با JavaScript کامل کنید.

**‫نکته مهم**: ‫این مستندات به صورت RTL (راست به چپ) نوشته شده است و باید در مرورگرهای فارسی نمایش داده شود.

## ‫آنچه باید انجام دهید

‫شما باید یک رابط کاربری کامل برای سیستم مدیریت کتابخانه بسازید که شامل موارد زیر باشد:

1. **‫صفحه ورود** - ‫کاربران بتوانند وارد سیستم شوند
2. **‫داشبورد دانشجو** - ‫نمایش آمار و اطلاعات شخصی
3. **‫صفحه کتاب‌ها** - ‫نمایش لیست کتاب‌ها و امکان امانت گرفتن
4. **‫صفحه امانت‌های من** - ‫مدیریت کتاب‌های امانت گرفته شده
5. **‫مدیریت احراز هویت** - ‫ورود، خروج و حفظ وضعیت کاربر

## ‫شروع کار

### 1. ‫دریافت فایل‌های پروژه

‫ابتدا فایل‌های قالب پروژه را از مخزن کلون کنید:

```bash
git clone git@github.com:karyar-js11/library-management-system-template.git
cd library-management-system-template
```

### 2. ‫آدرس API

‫بک‌اند پروژه روی سرور قرار گرفته و در دسترس است:

**‫آدرس پایه API**: `https://karyar-library-management-system.liara.run/api/`

**‫مستندات API**: `https://karyar-library-management-system.liara.run/api/docs/`

### 3. ‫ساختار فایل‌ها

‫پس از کلون کردن، ساختار فایل‌ها به این صورت خواهد بود:

```
library-templates/
├── css/
│   └── style.css          # استایل‌های آماده
├── js/                    # پوشه کدهای JavaScript شما
├── images/                # پوشه تصاویر
├── index.html             # صفحه اصلی
├── login.html             # صفحه ورود
├── dashboard.html # داشبورد دانشجو
├── books.html             # صفحه کتاب‌ها
├── my-loans.html          # صفحه امانت‌های من
└── README.md              # این فایل
```

## اطلاعات ورود

### کاربران موجود در سیستم

**دانشجویان (20 نفر):**
- نام کاربری: آدرس ایمیل واقعی دانشجویان
- رمز عبور: رمز عبور جداگانه برای هر دانشجو (ارسال شده از طریق ایمیل)

### داده‌های موجود

- **53 کتاب** در 10 دسته‌بندی مختلف
- **20 دانشجو** با اطلاعات کامل

## ‫API های موجود

### ‫احراز هویت
- `POST /api/auth/login` - ‫ورود کاربر
- `GET /api/auth/me` - ‫دریافت پروفایل و آمار کاربر

### ‫کتاب‌ها
- `GET /api/books` - ‫دریافت لیست تمام کتاب‌ها
- `GET /api/books/:id` - ‫دریافت جزئیات یک کتاب

### ‫امانت‌ها
- `GET /api/loans/my-loans` - ‫دریافت امانت‌های کاربر
- `POST /api/loans` - ‫امانت گرفتن کتاب
- `POST /api/loans/:id/return` - ‫بازگرداندن کتاب

### ‫نحوه استفاده از API

‫برای استفاده از API ها، باید درخواست‌های HTTP ارسال کنید. تمام درخواست‌ها (به جز ورود) نیاز به توکن JWT دارند که باید در header ارسال شود.

## ‫وظایف شما

### 1. ‫صفحه ورود (login.html)
- ‫فرم ورود با فیلدهای ایمیل و رمز عبور
- ‫ارسال درخواست به API برای ورود
- ‫ذخیره توکن JWT در کوکی (بدون HttpOnly)
- ‫هدایت به داشبورد پس از ورود موفق
- ‫نمایش پیام خطا در صورت ورود ناموفق

**‫فرآیند ورود:**
1. ‫کاربر ایمیل و رمز عبور را وارد می‌کند
2. ‫درخواست POST به `/api/auth/login` ارسال می‌شود
3. ‫در صورت موفقیت، توکن JWT دریافت می‌شود
4. ‫توکن در کوکی ذخیره می‌شود (بدون HttpOnly)
5. ‫کاربر به صفحه داشبورد هدایت می‌شود

### 2. ‫داشبورد دانشجو (dashboard.html)
- ‫نمایش نام کاربر
- ‫نمایش آمار (تعداد امانت‌های فعال، کتاب‌های موجود)
- ‫دکمه‌های دسترسی سریع
- ‫بارگذاری اطلاعات از API

### 3. ‫صفحه کتاب‌ها (books.html)
- ‫نمایش لیست کتاب‌ها در قالب کارت
- ‫نمایش اطلاعات: عنوان، نویسنده، ISBN، دسته‌بندی، تعداد موجود
- ‫دکمه امانت گرفتن برای کتاب‌های موجود
- ‫دکمه غیرفعال برای کتاب‌های ناموجود
- **‫کش کردن نتایج API** ‫برای 5 دقیقه در localStorage

### 4. ‫صفحه امانت‌های من (my-loans.html)
- ‫نمایش لیست امانت‌های کاربر
- ‫نمایش اطلاعات کتاب و تاریخ امانت
- ‫دکمه بازگرداندن کتاب
- ‫آمار امانت‌ها

### 5. ‫مدیریت احراز هویت
- ‫بررسی وجود توکن در کوکی
- ‫هدایت به صفحه ورود در صورت عدم وجود توکن
- ‫اضافه کردن توکن به درخواست‌های API
- ‫خروج از سیستم و پاک کردن توکن

### 6. ‫حفاظت از صفحات
- **‫کاربران غیروارد**: ‫فقط می‌توانند صفحات `index.html` و `login.html` را ببینند
- **‫کاربران وارد شده**: ‫نمی‌توانند `login.html` را ببینند و باید به داشبورد هدایت شوند
- **‫بررسی وضعیت ورود**: ‫در هر صفحه بررسی شود که کاربر وارد شده است یا نه

## ‫نکات مهم

### ‫احراز هویت
- ‫تمام درخواست‌های API (به جز ورود) نیاز به توکن JWT دارند
- ‫توکن را در header با نام `Authorization` و مقدار `Bearer <token>` ارسال کنید
- ‫توکن را در کوکی ذخیره کنید (بدون HttpOnly)

### ‫مدیریت خطا
- ‫همیشه پاسخ API را بررسی کنید
- ‫در صورت خطا، پیام مناسب نمایش دهید
- ‫وضعیت loading را برای کاربر نشان دهید

### ‫طراحی
- ‫از استایل‌های آماده در فایل `style.css` استفاده کنید
- ‫طراحی واکنش‌گرا (responsive) را رعایت کنید
- ‫تجربه کاربری مناسب فراهم کنید

### ‫نکات فنی

**‫ذخیره توکن در کوکی:**
- ‫از `document.cookie` برای ذخیره و بازیابی توکن استفاده کنید
- ‫توکن را بدون HttpOnly ذخیره کنید تا JavaScript بتواند به آن دسترسی داشته باشد
- ‫در هر درخواست API، توکن را از کوکی بخوانید و در header ارسال کنید

**‫کش کردن داده‌ها:**
- ‫نتایج API کتاب‌ها را برای 5 دقیقه در localStorage ذخیره کنید
- ‫قبل از درخواست جدید، ابتدا بررسی کنید که آیا داده‌های کش شده معتبر هستند یا نه
- ‫در صورت منقضی شدن کش، درخواست جدید ارسال کنید

**‫حفاظت از صفحات:**
- ‫در ابتدای هر صفحه (به جز index و login)، بررسی کنید که کاربر وارد شده است
- ‫اگر کاربر وارد نشده، به صفحه login هدایت کنید
- ‫اگر کاربر وارد شده و در صفحه login است، به داشبورد هدایت کنید

توضیحات صفحه ورود
استاد قالب صفحه رو داده بود و من با جاوااسکریپت، صفحه‌ی ورود رو کامل کردم.
اول با اضافه کردن یک شنونده به فرم، وقتی کاربر دکمه رو می‌زد یا اینتر می‌زد، جلوی بارگذاری مجدد صفحه رو گرفتم تا صفحه دوباره رفرش نشه و بتونم درخواست رو خودم مدیریت کنم.
بعد چک کردم که کاربر ایمیل و پسورد رو پر کرده باشه؛ اگه نه، زیر هر کدوم یه پیام خطا نشون دادم.
بعدش با ابزار درخواست‌دهنده، یه درخواست از نوع ارسال اطلاعات به سرور فرستادم که توش ایمیل و پسورد رو به صورت متن ساختاریافته فرستادم.
اگه سرور جواب درست بده، یه کلید امنیتی برمی‌گردونه که من اون رو توی حافظه‌ی مرورگر ذخیره می‌کنم و کاربر رو به صفحه‌ی اصلی می‌برم.
اگه خطایی بیاد، پیام خطا رو به کاربر نشون می‌دم.
برای اینکه کاربر دوبار روی دکمه کلیک نکنه، موقع ارسال دکمه رو غیرفعال می‌کنم و بعد از تموم شدن کار، دوباره فعالش می‌کنم.
همه‌ی این کارها رو توی فایل مربوط به جاوااسکریپت نوشتم.



توضیحات صفحه داشبورد
در صفحه‌ی داشبورد، اول از همه یک بررسی انجام می‌دهم که ببینم آیا کاربر قبلاً وارد سیستم شده یا نه. برای این کار، توکنی که در صفحه‌ی ورود در مرورگر کاربر ذخیره شده بود را از کوکی می‌خوانم. اگر این توکن وجود نداشته باشد، یعنی کاربر هنوز وارد نشده و او را به صفحه‌ی ورود هدایت می‌کنم.

بعد از اینکه وجود توکن را تأیید کردم، از همان توکن برای دریافت اطلاعات کاربر استفاده می‌کنم. با ارسال یک درخواست از نوع «گرفتن» به سرور، اطلاعات کاربری مثل نام و نام خانوادگی را دریافت کرده و در بخش مربوط به پروفایل کاربر در صفحه نمایش می‌دهم.

برای قسمت آمار نیز دو درخواست دیگر از نوع «گرفتن» به سرور می‌فرستم. یکی برای دریافت تعداد کل کتاب‌های موجود در کتابخانه و دیگری برای دریافت تعداد کتاب‌هایی که این کاربر به امانت گرفته است. بعد از دریافت اعداد، آن‌ها را در بخش آمار صفحه قرار می‌دهم.

در انتها، برای دکمه‌ی خروج، یک شنونده برای رویداد کلیک تعریف کرده‌ام. وقتی کاربر روی این دکمه کلیک کند، توکن از کوکی پاک می‌شود و کاربر به صفحه‌ی ورود هدایت می‌شود. این کار باعث می‌شود که فرد دیگری نتواند با استفاده از مرورگر کاربر، وارد سیستم شود.




صفحه کتاب ها
توی صفحه‌ی کتاب‌ها، اول یه درخواست به سرور فرستادم تا فهرست کتاب‌ها رو بگیرم. نشانه‌ی هویتی که توی حافظه‌ی مرورگر ذخیره شده بود رو برداشتم و توی سرصفحه‌ی درخواست گذاشتم تا سرور منو بشناسه.

وقتی داده‌ها از سرور اومد، اون قسمتی که استاد توی صفحه طراحی کرده بود و پر از کارت‌های ثابت بود رو خالی کردم. چون می‌خواستم کتاب‌ها به صورت پویا و از روی داده‌های سرور ساخته بشن، نه اینکه از قبل توی صفحه نوشته شده باشن.

بعد برای هر کتاب، یه کارت ساختم و اطلاعاتش رو توش گذاشتم. اطلاعاتی که توی هر کارت نمایش می‌دم شامل عنوان کتاب، نویسنده، شماره‌ی شابک، دسته‌بندی و تعداد موجودی کتابه. برای اینکه ظاهرش هم شبیه کارت‌های استاد باشه، از همون کلاس‌ها و سبک‌هایی که استاد توی شیوه‌نامه طراحی کرده بود استفاده کردم.

توی هر کارت، یه دکمه هم برای امانت گرفتن گذاشتم. این دکمه دو حالت داره:
اگه کتاب موجود باشه، دکمه‌ی «امانت گرفتن» فعال میشه.
اگه کتاب موجود نباشه، دکمه‌ی «موجود نیست» غیرفعال میشه و کاربر نمی‌تونه روش کلیک کنه.

برای اینکه دکمه‌ی امانت کار کنه، بعد از اینکه کارت‌ها ساخته شدن، به دکمه‌ی هر کارت یه شنونده‌ی رویداد کلیک وصل کردم. وقتی کاربر روی دکمه کلیک می‌کنه، تابع امانت گرفتن صدا زده میشه و یه درخواست به سرور فرستاده میشه. توی این درخواست، اطلاعات کتاب، اطلاعات کاربر، مدت امانت (چهارده روز) و تاریخ برگرداندن کتاب رو می‌فرستم. نشانه‌ی هویت هم توی سرصفحه‌ی درخواست قرار می‌گیره.

برای بخش نگهداری موقت، دو تا تابع جدا در نظر گرفتم:
یکی برای گرفتن داده‌ها از سرور و ذخیره‌شون توی حافظه‌ی مرورگر، و یکی هم برای نمایش کتاب‌ها توی صفحه.

توی حافظه‌ی مرورگر، یه کلید ذخیره می‌کنم که توش دو چیز هست: داده‌های کتاب‌ها و زمان ذخیره‌سازی.

وقتی کاربر صفحه رو باز می‌کنه، اول چک می‌کنم که آیا داده‌ای توی حافظه‌ی مرورگر هست یا نه. اگه بود، چک می‌کنم که از زمان ذخیره‌سازی کمتر از پنج دقیقه گذشته یا نه:
اگه کمتر از پنج دقیقه گذشته باشه، یعنی داده‌های موقت هنوز معتبرن و از همون‌ها استفاده می‌کنم. دیگه درخواست جدیدی به سرور نمی‌فرستم.
اگه بیشتر از پنج دقیقه گذشته باشه، یعنی داده‌های موقت منقضی شدن. پس دوباره از سرور داده می‌گیرم، داده‌های موقت رو به‌روز می‌کنم و فهرست کتاب‌ها رو از اول می‌سازم.

یه نکته‌ی مهم هم درباره‌ی نگهداری موقت: بعد از اینکه کاربر یه کتاب رو امانت می‌گیره، چون تعداد موجودی اون کتاب کم شده، داده‌های موقت قبلی دیگه معتبر نیستن. برای همین بعد از امانت گرفتن، داده‌های موقت رو پاک می‌کنم و صفحه رو دوباره بارگذاری می‌کنم تا اطلاعات جدید از سرور گرفته بشه و به کاربر نمایش داده بشه.


صفحه امانت های من
توی صفحه‌ی امانت‌های من، اول توکن کاربر رو از حافظه‌ی مرورگر برداشتم. اگه توکن نبود، کاربر رو فرستادم به صفحه‌ی ورود.

بعد بدنه‌ی جدولی که استاد طراحی کرده بود رو خالی کردم. چون می‌خواستم اطلاعات امانت‌ها از سرور بیان و توی جدول نمایش داده بشن، نه اینکه از قبل توی صفحه نوشته شده باشن. من هیچ کد سی‌اس‌اس‌ای ننوشتم، همه‌ی استایل‌ها و کلاس‌ها از خود استاد بود.

بعد یه درخواست فرستادم به سرور تا اسم کاربر رو بگیرم. اسم کوچیک کاربر رو از جواب سرور برداشتم و توی بالای صفحه گذاشتم.

بعد یه درخواست دیگه فرستادم به سرور تا لیست امانت‌های کاربر رو بگیرم. توکن رو هم توی هدر درخواست گذاشتم تا سرور منو بشناسه.

وقتی اطلاعات امانت‌ها از سرور اومد، اول رفتم آمارشون رو حساب کنم. با یه حلقه‌ی تکرار روی همه‌ی امانت‌ها گشتم. دو تا شمارنده گذاشتم؛ یکی برای امانت‌های فعال و یکی برای کتاب‌های برگردانده شده. توی هر دور حلقه، چک کردم که اگه وضعیت امانت فعال بود، شمارنده‌ی اول رو یکی زیاد کنم و اگه برگردانده شده بود، شمارنده‌ی دوم رو یکی زیاد کنم. آخرش این دو تا عدد رو گذاشتم توی صفحه.

حالا برای نمایش لیست امانت‌ها، با یه حلقه‌ی تکرار دیگه روی همه‌ی امانت‌ها گشتم و برای هر امانت یه ردیف جدول ساختم و گذاشتمش توی بدنه‌ی جدول. توی هر ردیف، عنوان کتاب، شماره‌ی شابک، نویسنده، تاریخ امانت و وضعیتش رو گذاشتم. برای تاریخ امانت، با یه دستور فقط قسمت تاریخش رو جدا کردم تا ساعتش نمایش داده نشه.

برای دکمه‌ی بازگرداندن، از همون ساختار و کلاس‌هایی که استاد گذاشته بود استفاده کردم، فقط یه شناسه بهش اضافه کردم تا بدونم هر دکمه مال کدوم امانته. با یه شرط چک کردم که اگه امانت فعال بود، دکمه‌ی سبز بسازم که کاربر بتونه کتاب رو برگردونه. اگه برگردانده شده بود، دکمه‌ی خاکستری می‌سازم و با ویژگی غیرفعال قفلش می‌کنم تا کاربر نتونه روش کلیک کنه.

برای اینکه دکمه‌ی بازگرداندن کار کنه، بعد از ساختن هر ردیف، با یه دستور انتخاب‌گر دکمه‌ی داخل اون ردیف رو پیدا کردم و یه شنونده‌ی کلیک بهش اضافه کردم. وقتی کاربر روی این دکمه کلیک می‌کنه، تابع بازگرداندن صدا زده میشه و شناسه‌ی اون امانت رو بهش می‌دم.

توی تابع بازگرداندن، یه درخواست از نوع فرستادن به سرور فرستادم. شناسه‌ی امانت رو توی خود آدرس گذاشتم و توکن رو توی هدر درخواست گذاشتم. وقتی سرور کتاب رو با موفقیت برگردوند، یه پیام موفقیت نشون دادم و صفحه رو دوباره بارگذاری کردم تا آمار و لیست امانت‌ها به‌روز بشن و کاربر ببینه که کتاب برگردانده شده.



مدیریت احراز هویت
من توی صفحه‌ی ورود، چک کردم که اگه کاربر قبلاً وارد شده و توکن داره، به داشبورد هدایت بشه. و توی صفحات دیگه، چک کردم که اگه کاربر توکن نداره، به صفحه‌ی ورود هدایت بشه. این کار باعث می‌شه کاربران وارد شده نتونن صفحه‌ی ورود رو ببینن و کاربران وارد نشده نتونن به صفحات محافظت‌شده دسترسی داشته باشن.
